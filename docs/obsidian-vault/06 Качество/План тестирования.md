# План тестирования

## Frontend

| Проверка | Команда/способ | Ожидание |
|---|---|---|
| TypeScript + build | `npm run build` | без ошибок |
| Главный экран | ручной запуск Vite | файл выбирается, вопрос отправляется |
| `/help` | открыть `/help` | видны hero, шаги, скриншоты, кнопка назад |
| Адаптив | desktop/tablet/mobile | кнопка `?` не перекрывает логотип, текст не ломается |
| Ошибка backend | выключить backend | пользователь видит понятную ошибку |

## Backend

| Проверка | Команда/способ | Ожидание |
|---|---|---|
| Unit/API tests | `python -m pytest` | все тесты проходят |
| Ruff | `ruff check .` | без нарушений |
| Format check | `ruff format --check .` | без изменений |
| Health | `GET /health` | `{"status":"ok"}` |
| Analyze | `POST /analyze` | JSON с `ocr_text` и `fields` |

## OCR-кейсы

- Хороший PNG справки об обучении.
- Одностраничный PDF.
- Файл больше 10 МиБ.
- PDF с несколькими страницами.
- Пустой/битый файл.
- Плохое фото с перспективой.
- Даты через точки, дефисы, пробелы.
- Раздельная метка и значение в разных OCR-блоках.
- Подпись и печать есть.
- Подписи и печати нет, но слова «Подпись» и «М.П.» напечатаны.

## Метрики

- Доля найденных обязательных полей по каждому типу.
- Количество ложных найденных дат.
- Количество случаев `не найдено`.
- Время обработки на CPU.
- Размер файла и поведение на лимитах.

## Минимальная smoke-проверка

1. Запустить backend на `127.0.0.1:8000`.
2. Запустить frontend.
3. Выбрать «Справка об обучении».
4. Загрузить тестовый PNG/PDF.
5. Ввести вопрос.
6. Проверить, что результат появился и поля не пустые.
7. Открыть `/help` через кнопку `?`.
