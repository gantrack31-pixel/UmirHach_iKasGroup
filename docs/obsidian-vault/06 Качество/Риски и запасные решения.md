# Риски и запасные решения

| Риск | Влияние | Как понять | План B |
|---|---|---|---|
| EasyOCR плохо читает дату | Высокое | `issue_date` или периоды `не найдено` | Улучшить preprocessing, добавить date parser по OCR-тексту, показать ручную проверку |
| OCR путает кавычки/буквы | Среднее | «кМеридианх» вместо «Меридиан» | Не подставлять эталон, показывать OCR как есть |
| Backend тяжёлый на CPU | Среднее | долгий первый запуск/ответ | предупредить в README, ограничить очередь, демо на подготовленном окружении |
| Frontend не достучался до backend | Высокое | fetch error | понятный текст ошибки, demo-mode как запасной показ UI |
| Нормативная проверка не готова | Критичное | нет `rule_id`/Положения | честно оставить статус OCR MVP, не обещать решение |
| Утечка данных | Критичное | реальные документы/логи в Git | только синтетика, проверка `git status`, не логировать OCR-текст |
| Лишние dirty-файлы попали в PR | Среднее | `git diff --cached` показывает чужие файлы | добавлять файлы явно, перед PR смотреть staged diff |
| Скриншоты `/help` устареют | Низкое | UI изменился, help не совпадает | обновлять `frontend/assets/help/*.png` вместе с UI |

## Стоп-условия

- Не выпускать формулировки «документ подходит по Положению», пока нет слоя правил.
- Не мержить PR, если в нём случайно есть приватные файлы или реальные документы.
- Не использовать внешние OCR/LLM API без явного разрешения регламента.

## Текущие известные проблемы

- OCR иногда плохо читает дату.
- README фичи document-check отстаёт от реального API-режима.
- В рабочем дереве есть незакоммиченные изменения не из PR `#6`.
