# Работа с датасетом организаторов

## Что хранить где

- Публичные синтетические примеры можно хранить в репозитории, если они не содержат персональных данных.
- Официальный или приватный датасет хранить локально вне Git, например `data/private`.
- Не добавлять реальные документы студентов в Obsidian vault.

## Что проверить по каждому типу

| Тип | Поля | Особые риски |
|---|---|---|
| Справка об обучении | ФИО, вуз, программа, форма, период, номер, дата, подпись, печать | даты, кавычки в названии вуза, подпись/печать |
| Заявление на академический отпуск | ФИО, группа/курс, причина, период, дата заявления, подпись | свободный текст причины, разные формулировки периода |
| Справка о практике | ФИО, организация, период, руководитель, оценка, дата, подпись, печать | названия организаций, оценка, печать |

## Протокол проверки OCR

1. Для каждого документа сохранить ожидаемые поля вручную в локальной таблице.
2. Прогнать `/analyze` с правильным `document_type`.
3. Сравнить каждое поле:
   - найдено верно;
   - найдено с OCR-ошибкой;
   - не найдено;
   - найдено ложное значение.
4. Отдельно фиксировать ошибки дат.
5. Не исправлять OCR подстановкой известных значений без правила.
