# Онлайн-деканат — стартовая панель

> [!abstract] Текущее состояние
> Проект уже имеет рабочий frontend на React/Vite и отдельный FastAPI backend с локальным EasyOCR. Основной пользовательский поток: выбрать тип документа, загрузить JPG/PNG/PDF, задать вопрос, отправить файл в `/analyze`, получить OCR-текст и карточку найденных полей. Отдельная страница `/help` объясняет процесс с реальными скриншотами.

## Что ещё не закрыто

- Ответ на вопрос пока не является полноценной проверкой по Положению: backend валидирует вопрос и возвращает распознавание, frontend формирует краткий статус по найденным полям.
- Экспорт `results.json` по официальной схеме не реализован.
- Качество EasyOCR надо проверять на полном наборе организаторов, особенно даты, кавычки, печати и нестандартные макеты.
- README фичи `frontend/src/features/document-check/README.md` ещё отстаёт от кода: в нём описан demo-режим как основной, хотя сейчас основной сервис — API.

## Команды запуска

Backend:

```bash
cd backend/online-dekanat-backend
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch==2.14.1 torchvision==0.29.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Frontend:

```bash
cd frontend
npm install
npm run dev
```

Если frontend запускается отдельно, API ожидается на `/ocr-api`. Для прямого адреса backend можно задать `VITE_OCR_API_URL=http://127.0.0.1:8000`.

## Рабочие правила

- В публичный GitHub не добавлять реальные студенческие документы, `.env`, модели OCR и приватные датасеты.
- Любое изменение API сразу отражать в [[02 Техника/Контракт API]].
- Не выдавать OCR-результат за юридически значимое решение: если поле не найдено или OCR ошибся, показывать неопределённость.
- Перед PR запускать `npm run build` для frontend и `python -m pytest` для backend, если менялся соответствующий слой.
