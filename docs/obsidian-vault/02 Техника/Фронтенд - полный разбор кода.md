# Фронтенд - полный разбор кода

## Назначение

Frontend даёт пользователю один рабочий сценарий:

1. выбрать тип документа;
2. загрузить файл;
3. задать вопрос;
4. отправить всё в OCR backend;
5. увидеть найденные поля, статус и текстовое основание;
6. при необходимости открыть `/help`.

## Точка входа

`frontend/src/App.tsx`:

```tsx
return window.location.pathname === "/help" ? <HelpPage /> : <DocumentCheckerPage />;
```

Пока нет React Router. Для двух страниц этого достаточно:

- `/` и любые остальные пути показывают `DocumentCheckerPage`;
- `/help` показывает `HelpPage`.

## Главная страница проверки

Файл: `frontend/src/pages/DocumentCheckerPage.tsx`.

Компоненты:

- `HeroSection` — верхний блок, логотип, заголовок, кнопка справочника `?`;
- `DocumentUploadPanel` — тип документа, drag-and-drop, выбранный файл;
- `ExtractedFieldsPanel` — список найденных полей;
- `CheckResultPanel` — итоговый статус, ответ помощника, OCR-источник;
- `QuestionForm` — вопрос студента и кнопка проверки;
- `SiteFooter` — нижняя подпись.

## Состояние

Состояние живёт в `useDocumentCheck`.

Он использует:

- `documentCheckReducer`;
- `initialDocumentCheckState`;
- `validateUploadedFile`;
- `validateDocumentCheckInput`;
- выбранный `DocumentCheckService`.

Основные действия:

- `addFile(file)` — проверка файла и сохранение в состоянии;
- `removeFile()` — очистка файла;
- `setQuestion(question)` — обновление вопроса;
- `setDocumentType(type)` — смена типа документа;
- `runCheck()` — валидация и запуск сервиса.

## Сервисный слой

Файл: `frontend/src/features/document-check/services/documentCheckService.ts`.

По умолчанию используется:

```ts
new ApiDocumentCheckService()
```

Demo включается только если:

```text
VITE_USE_DEMO_SERVICE=true
```

Это важно: старая документация фичи ещё говорит, что demo — основной режим, но код уже перешёл на API.

## API-клиент

Файл: `ApiDocumentCheckService.ts`.

Что делает:

1. Берёт `file`, `question`, `documentType`.
2. Создаёт `FormData`.
3. Отправляет `POST ${OCR_API_URL}/analyze`.
4. Обрабатывает ошибки `413`, `422`, `503`.
5. Мапит backend response в `DocumentCheckResult`.

Адрес API:

```ts
const OCR_API_URL = VITE_OCR_API_URL || "/ocr-api";
```

Для локальной разработки можно использовать proxy в Vite или задать прямой адрес backend.

## Типы документов

Файл: `data/documentTypes.ts`.

Текущий статический список:

- `study_certificate` — справка об обучении;
- `academic_leave_application` — заявление на академический отпуск;
- `internship_certificate` — справка о практике.

Backend принимает те же enum-значения.

## Страница справки `/help`

Файл: `frontend/src/pages/HelpPage.tsx`.

Страница статичная, backend не вызывает. Состоит из:

- hero с заголовком и кнопкой возврата;
- блока тестового документа;
- массива `steps` с четырьмя шагами;
- блока советов для OCR.

Скриншоты лежат в `frontend/assets/help/`:

- `help-step-upload-empty.png`;
- `help-step-upload-selected.png`;
- `help-step-question.png`;
- `help-step-result.png`.

Кнопка возврата использует `Icon name="arrow-left"` и ведёт на `/`.

## Кнопка справочника в hero

Файл: `HeroSection.tsx`.

Кнопка:

```tsx
<a className="hero-help-button" href="/help" aria-label="Открыть справочник">
  <Icon name="help" size={32} />
</a>
```

Размер управляется CSS через `clamp`, поэтому кнопка уменьшается на мобильных экранах и стоит на уровне логотипа.

## Стили

Главный импорт: `frontend/src/styles.scss`.

Частичные файлы:

- `_base.scss` — CSS-переменные, базовые стили;
- `_layout.scss` — оболочка и сетка;
- `_hero.scss` — hero и кнопка справочника;
- `_upload.scss` — загрузка файла;
- `_fields.scss` — найденные поля;
- `_results.scss` — статус и ответ;
- `_question-footer.scss` — форма вопроса и footer;
- `_help.scss` — страница `/help`;
- `_responsive.scss` — адаптив.

## Сборка

```bash
cd frontend
npm run build
```

Команда выполняет:

```bash
tsc --noEmit && vite build
```
