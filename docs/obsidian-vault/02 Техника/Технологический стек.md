# Технологический стек

## Frontend

| Слой | Выбор | Где |
|---|---|---|
| UI | React 18 | `frontend/src/` |
| Сборка | Vite 5 | `frontend/vite.config.ts` |
| Типизация | TypeScript | `tsconfig` + `npm run build` |
| Стили | SCSS/Sass | `frontend/src/styles*.scss` |
| Иконки | Собственный компонент `Icon` | `frontend/src/shared/components/Icon.tsx` |

Команды:

```bash
cd frontend
npm install
npm run dev
npm run build
```

Переменные:

| Переменная | Значение |
|---|---|
| `VITE_OCR_API_URL` | Адрес backend; по умолчанию `/ocr-api` |
| `VITE_USE_DEMO_SERVICE=true` | Включить demo-сервис вместо API |

## Backend

| Слой | Выбор | Где |
|---|---|---|
| API | FastAPI | `backend/online-dekanat-backend/main.py` |
| Валидация | Pydantic + FastAPI forms | `AnalyzeResponse`, `DocumentType` |
| OCR | EasyOCR 1.7.2 | `services/ocr_service.py` |
| PDF | PyMuPDF | `services/document_loader.py` |
| Изображения | Pillow, OpenCV, NumPy | loader + marks service |
| Тесты | pytest, ruff | `requirements-test.txt` |

Команды:

```bash
cd backend/online-dekanat-backend
python -m pip install -r requirements-test.txt
python -m pytest
ruff check .
ruff format --check .
```

Для настоящего OCR нужны зависимости из `requirements.txt` и CPU-сборки PyTorch/torchvision, как описано в backend README.

## Почему EasyOCR

Текущая реализация уже использует EasyOCR. Старые заметки про PaddleOCR/RapidOCR считаются историческим планом. RapidOCR можно оставить как запасной вариант, если EasyOCR окажется слишком тяжёлым или нестабильным на документах организаторов.

## Ограничения производительности

- Первый запуск скачивает модели EasyOCR.
- CPU-инференс может быть медленным.
- Один процесс backend обрабатывает OCR по одному запросу.
- `--reload` в разработке перезагружает модель.
- `--workers` без расчёта памяти может загрузить несколько экземпляров модели.

## Что не используется

- Внешние LLM API.
- Внешние OCR API.
- Tailwind CSS.
- База данных в текущем MVP.
