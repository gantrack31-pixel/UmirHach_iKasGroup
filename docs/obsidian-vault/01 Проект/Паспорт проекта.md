## 📌 Задача
Создать цифрового секретаря деканата, который принимает JPG/PNG/PDF, распознаёт содержимое студенческого документа, извлекает проверяемые поля, сверяет их с Положением и отвечает на вопрос со ссылкой на **существующий** пункт.

## 🔎 Обязательный MVP
1. Загрузка файлов; валидация формата/размера.
2. OCR русского текста и проверка качества.
3. Определение трёх типов: справка об обучении; заявление на академический отпуск; справка о практике (проверить названия и поля по датасету).
4. Извлечение обязательных реквизитов; явное различие `не найдено` и `отсутствует`.
5. Детерминированный движок правил, поиск пункта и отсутствие выдуманных норм.
6. Ответ на вопрос; отказ от категоричного вывода при недостатке данных.
7. Экспорт `results.json` **точно по официальной схеме**.

## Бонусы после MVP
Автоопределение типа документа; улучшение фото; подсветка OCR-блоков; новые типы через конфиг; локальная LLM для естественного языка.

## Ограничения
- Внешние LLM API (YandexGPT, GigaChat и аналоги) запрещены по заявленному кейсу.
- CPU-only — целевой режим. Правила насчёт предобученных OCR/локальных моделей и доступа к интернету уточнить в полном регламенте.
- Не допускать передачи пользовательских файлов третьим лицам.

## Ключевые решения
- Source of truth для фактов: OCR + поля + валидированное Положение.
- LLM **не принимает нормативных решений**: только перефразирует подготовленное заключение; шаблонный fallback.
- Отсутствие подписи/печати — это отдельная визуальная задача, не доказательство по наличию слова «печать».

## Вопросы к организаторам
- Каковы реальные названия/форматы входных файлов и образец `results.json`?
- Что считается успешной ссылкой на пункт: номер, дословный текст или ID?
- Запрещены ли вообще внешние сети или только API языковых моделей?
- Нужно ли строго запускать все компоненты на CPU?
- Каков лимит времени на один документ?
