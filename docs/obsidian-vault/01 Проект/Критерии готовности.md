# Критерии готовности

## Выполнено

- [x] Есть React/Vite frontend с основным экраном проверки.
- [x] Есть отдельная страница `/help` с реальными скриншотами процесса.
- [x] Есть кнопка справочника `?` в hero, ведущая на `/help`.
- [x] Frontend валидирует файл, тип документа и вопрос до отправки.
- [x] Frontend по умолчанию отправляет файл в OCR API.
- [x] Backend принимает один JPG/PNG или одностраничный PDF.
- [x] Backend ограничивает размер файла и тела запроса.
- [x] Backend возвращает поля для трёх типов документов.
- [x] Backend имеет тесты с подменой OCR.
- [x] Сборка frontend проходит через `npm run build`.

## Частично выполнено

- [~] OCR работает локально, но качество дат и нестандартных макетов требует проверки на полном наборе.
- [~] Подпись и печать определяются, но только эвристически.
- [~] UI показывает статус по найденным полям, но это ещё не юридическая проверка по Положению.

## Не выполнено

- [ ] Подключить детерминированные правила Положения.
- [ ] Возвращать реальные `rule_id` и доказательства.
- [ ] Сделать экспорт `results.json` по официальной схеме.
- [ ] Обновить `frontend/src/features/document-check/README.md` под API-режим.
- [ ] Прогнать EasyOCR на полном официальном наборе документов.
- [ ] Подготовить финальное демо/видео и презентацию.

## Минимальная проверка перед сдачей

Frontend:

```bash
cd frontend
npm run build
```

Backend:

```bash
cd backend/online-dekanat-backend
python -m pytest
ruff check .
ruff format --check .
```
