### 👤 Задачи по исполнителям

#### Кирилл — Backend

- [ ] **3.1 Нормализовать данные** — ФИО, даты, номера, периоды, форма обучения; учесть похожие символы OCR.
  - **Критерий готовности:** Unit-тесты на корректные и испорченные значения. **Артефакт:** Модуль normalizer.
- [ ] **3.2 Реализовать 3 парсера** — Справка об обучении, заявление на академотпуск, справка о практике; сохранять source bbox.
  - **Критерий готовности:** Сверить по 2 примерам на тип. **Артефакт:** Parser registry.

#### Арсений — Frontend

- [ ] **3.1 Сделать карточку полей** — Таблица поле/значение/достоверность; null → «не найдено».
  - **Критерий готовности:** Проверить все 3 типа. **Артефакт:** Результат понятен.
- [ ] **3.2 Добавить предупреждения** — Отображать отсутствие, низкую уверенность и ошибку распознавания по-разному.
  - **Критерий готовности:** Тест пустого поля и сомнительного. **Артефакт:** UX неопределённости.

#### Игорь — Fullstack

- [ ] **3.1 Составить матрицу ошибок** — Отметить минимум 10 проблем OCR, классифицировать по причинам.
  - **Критерий готовности:** В каждой строке есть способ повторной проверки. **Артефакт:** Бэклог качества.
- [ ] **3.2 Сверить форматы полей** — Сопоставить Pydantic, фронтовые типы, требования организаторов.
  - **Критерий готовности:** Пример JSON проходит контрактный тест. **Артефакт:** Совместимость API.

### 🚧 Если возникли проблемы

> [!warning] Приоритеты
> Сначала восстановить цепочку «файл → OCR → поля → правила → результат», затем улучшать интерфейс и локальную LLM. Если датасет или формат экспорта не выданы, работать на синтетических фикстурах, явно пометив их предварительными.

- [ ] Если работа остановлена более чем на один рабочий блок — записать блокер и назначить помощника.
- [ ] Если интеграция сломалась — вернуться к последнему рабочему сценарию и использовать моки/фолбэк.
- [ ] Если CPU-модель слишком медленная — отключить LLM и сохранить детерминированные ответы.
