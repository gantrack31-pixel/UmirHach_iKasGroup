### 👤 Задачи по исполнителям

#### Кирилл — Backend

- [ ] **6.1 Регрессионный pytest** — Позитив/негатив по каждому типу, повреждённые файлы, некорректные даты, таймауты.
  - **Критерий готовности:** Все блокирующие тесты зелёные. **Артефакт:** Отчёт тестов.
- [ ] **6.2 Проверить производительность** — Измерить на CPU время по этапам: PDF/OCR/fields/rules/LLM.
  - **Критерий готовности:** Привести p50/p95 где достаточно примеров. **Артефакт:** Таблица измерений.

#### Арсений — Frontend

- [ ] **6.1 E2E smoke Playwright** — Загрузка, распознавание, ошибки и отображение норм; сохранить скриншоты.
  - **Критерий готовности:** Тесты проходят минимум в одном браузере. **Артефакт:** Протокол UI.
- [ ] **6.2 Бонус при готовом MVP** — Подсветить OCR bbox или добавить превью; только после фикса базовых ошибок.
  - **Критерий готовности:** Фича отключаема и не влияет на ответы. **Артефакт:** Контролируемый бонус.

#### Игорь — Fullstack

- [ ] **6.1 Формировать results.json** — Точно повторить схему README организаторов, без самодельных полей.
  - **Критерий готовности:** JSON валиден на локальной проверке. **Артефакт:** Экспорт готов.
- [ ] **6.2 Проверить качество** — Ошибки извлечения, корректность rule_id, unknown cases; составить топ дефектов.
  - **Критерий готовности:** Каждый серьёзный дефект назначен и исправлен/описан. **Артефакт:** Решение о заморозке.

### 🚧 Если возникли проблемы

> [!warning] Приоритеты
> Сначала восстановить цепочку «файл → OCR → поля → правила → результат», затем улучшать интерфейс и локальную LLM. Если датасет или формат экспорта не выданы, работать на синтетических фикстурах, явно пометив их предварительными.

- [ ] Если работа остановлена более чем на один рабочий блок — записать блокер и назначить помощника.
- [ ] Если интеграция сломалась — вернуться к последнему рабочему сценарию и использовать моки/фолбэк.
- [ ] Если CPU-модель слишком медленная — отключить LLM и сохранить детерминированные ответы.
