### 👤 Задачи по исполнителям

#### Кирилл — Backend

- [ ] **4.1 Интегрировать правила** — POST /api/analyze возвращает fields, issues, citations и итоговый статус.
  - **Критерий готовности:** pytest проверяет наличие валидного rule_id. **Артефакт:** Готовый backend анализа.
- [ ] **4.2 Добавить защиту от выдумок** — Не выдавать номер пункта, если правило не сопоставлено; fallback «не найдено».
  - **Критерий готовности:** Тест отсутствующего правила. **Артефакт:** Никаких искусственных цитат.

#### Арсений — Frontend

- [ ] **4.1 Экран проверки документа** — Показать вывод, причины, статус и список пунктов Положения.
  - **Критерий готовности:** Демо 3 сценариев. **Артефакт:** Прозрачный интерфейс.
- [ ] **4.2 Улучшить проверяемость** — Раздел «На основании» с текстом и номером правила; кнопка нового анализа.
  - **Критерий готовности:** Пользователь видит основание каждого предупреждения. **Артефакт:** Проверяемые ответы.

#### Игорь — Fullstack

- [ ] **4.1 Разметить Положение** — Преобразовать пункты в rule_id, номер, точную формулировку, условия и исключения.
  - **Критерий готовности:** Ручная сверка 5+ ссылок с оригиналом. **Артефакт:** Каталог правил.
- [ ] **4.2 Написать Rule Engine** — Проверка обязательных полей/условий, статусы sufficient/insufficient/unknown.
  - **Критерий готовности:** Прогнать положительный, отрицательный, неопределённый случаи. **Артефакт:** Детерминированное решение.

### 🔗 Зависимости и передача результатов

- [ ] Кирилл сообщает API-маршруты, JSON-формат и изменения схемы Арсению и Игорю.
- [ ] Арсений проверяет интерфейс на реальном ответе и сообщает несовпадения схемы.
- [ ] Игорь сверяет результат с Положением/датасетом и фиксирует решение о готовности.
- [ ] Все изменения уходят через Git, без токенов, ключей и персональных данных в коммитах.

### 🧪 Приёмка дня

- [ ] На актуальной ветке воспроизводится основной сценарий дня.
- [ ] Есть ссылка на PR/коммит или файл с доказательством результата.
- [ ] Известные ошибки записаны с ответственным и сроком исправления.
- [ ] Ни один неизвестный пункт Положения не подменён выдуманным номером.

### 🚧 Если возникли проблемы

> [!warning] Приоритеты
> Сначала восстановить цепочку «файл → OCR → поля → правила → результат», затем улучшать интерфейс и локальную LLM. Если датасет или формат экспорта не выданы, работать на синтетических фикстурах, явно пометив их предварительными.

- [ ] Если работа остановлена более чем на один рабочий блок — записать блокер и назначить помощника.
- [ ] Если интеграция сломалась — вернуться к последнему рабочему сценарию и использовать моки/фолбэк.
- [ ] Если CPU-модель слишком медленная — отключить LLM и сохранить детерминированные ответы.
