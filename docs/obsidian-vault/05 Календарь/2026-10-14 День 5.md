### 👤 Задачи по исполнителям

#### Кирилл — Backend

- [ ] **5.1 Испытать Qwen3-1.7B CPU** — Локальный запуск Ollama/llama.cpp без внешнего API; замер задержки и памяти.
  - **Критерий готовности:** Протокол теста с реальными цифрами. **Артефакт:** Решение включать ли LLM.
- [ ] **5.2 Безопасная генерация** — Таймаут, ограничение входа и выходных полей; модель не меняет verdict/citations.
  - **Критерий готовности:** Сбой модели не ломает ответ. **Артефакт:** Контролируемый LLM слой.

#### Арсений — Frontend

- [ ] **5.1 Сделать сквозной UI** — Подключить реальные эндпоинты, показать все состояния обработки.
  - **Критерий готовности:** E2E сценарий из 3 шагов. **Артефакт:** Демо для жюри.
- [ ] **5.2 Полировка** — Адаптивность, доступные подписи, понятные ошибки/повторная попытка.
  - **Критерий готовности:** Проверка узкого окна и клавиатуры. **Артефакт:** Готовый UX.

#### Игорь — Fullstack

- [ ] **5.1 Соединить полный поток** — Загрузка → OCR → поля → правила → ответ; устранить несовпадения JSON.
  - **Критерий готовности:** Демо без ручного изменения ответа. **Артефакт:** Интегрированный сервис.
- [ ] **5.2 Шаблонные ответы** — Создать генератор ответа по issues/citations на случай сбоя LLM.
  - **Критерий готовности:** Отключить LLM и получить корректный ответ. **Артефакт:** Надёжный fallback.

### 🚧 Если возникли проблемы

> [!warning] Приоритеты
> Сначала восстановить цепочку «файл → OCR → поля → правила → результат», затем улучшать интерфейс и локальную LLM. Если датасет или формат экспорта не выданы, работать на синтетических фикстурах, явно пометив их предварительными.

- [ ] Если работа остановлена более чем на один рабочий блок — записать блокер и назначить помощника.
- [ ] Если интеграция сломалась — вернуться к последнему рабочему сценарию и использовать моки/фолбэк.
- [ ] Если CPU-модель слишком медленная — отключить LLM и сохранить детерминированные ответы.
