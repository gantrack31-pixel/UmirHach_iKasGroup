# StudDoc: Онлайн-деканат

Локальный прототип проверки студенческих документов. Студент выбирает тип,
загружает JPEG, PNG или одностраничный PDF и при желании задаёт вопрос. Приложение
распознаёт текст, показывает поля, предварительную комплектность и ответ
со ссылками на поля или пункты учебного Положения.

Поддерживаются справка об обучении, заявление на академический отпуск
и справка о практике. Все документы и правила из `data/` вымышлены.
Окончательное решение о принятии документа принимает сотрудник деканата.

Для проверки комплектности оставьте вопрос пустым и нажмите «Проверить
комплектность». Frontend отправит в `prompt` стандартный вопрос «Содержит ли
документ все обязательные сведения?». Backend обрабатывает его как обычный
непустой вопрос. Введённый пользователем вопрос отправляется без изменений.

Backend хранится обычными исходниками в `backend/online-dekanat-backend/`.
Изменения frontend и backend коммитятся в этот репозиторий; отдельный clone
backend или инициализация submodule не нужны. Модели и `.venv` не входят в Git.

## Структура проекта

```text
backend/online-dekanat-backend/   FastAPI, OCR, поля, валидация, классификация
frontend/                        React, TypeScript, Vite, SCSS и тесты UI-логики
data/                            документы, вопросы, Положение и эталон
docs/obsidian-vault/              общая документация команды
docker-compose.yml               прежний каркас Docker-запуска
```

Frontend разделён на страницы, фичи проверки и справочника, общие компоненты
и конфигурацию. API-запрос, проверка ответа и преобразование для UI находятся
в отдельных модулях. Подробная карта: [frontend/README.md](frontend/README.md).

## Запуск на macOS

Нужны Node.js 24 с npm и Python с поддержкой зависимостей backend.
Для текущей установки на Mac использовался Python 3.14. Платформенные
подробности Tesseract и модели: [README backend](backend/online-dekanat-backend/README.md).

Команды ниже выполняются из корня `Code`.

### Backend

При первой установке:

```bash
brew install tesseract
cd backend/online-dekanat-backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
mkdir -p models/tessdata
curl --fail --location https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/4.1.0/rus.traineddata --output models/tessdata/rus.traineddata
.venv/bin/python -m services.question_model --download --warmup
```

Команда подготовки скачивает локальную Qwen3-1.7B в `models/llm` и проверяет
запуск. Загрузчик использует CPU и FP32: только веса требуют около 7 ГБ RAM,
дополнительно нужна память для вычислений. Для первого скачивания нужен доступ
к Hugging Face.
Повторно устанавливать зависимости и скачивать готовую модель не требуется.

При проблемах со скачиванием через Xet можно использовать HTTP:

```bash
HF_HUB_DISABLE_XET=1 .venv/bin/python services/question_model.py --download --warmup
```

Для запуска из той же папки:

```bash
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

API: `http://127.0.0.1:8000`; Swagger: `http://127.0.0.1:8000/docs`.
`GET /health` проверяет доступность процесса, а не готовность моделей.

### Frontend

В другом терминале, из корня `Code`:

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес Vite, обычно `http://localhost:5173`.
Если порт занят, используйте адрес, напечатанный в терминале.
Страница проверки находится на `/`, справочник - на `/help`.

Dev-прокси передаёт `/ocr-api/analyze` на backend `127.0.0.1:8000/analyze`.
Настройки фронта задаются в `frontend/.env.local`:

```dotenv
VITE_USE_DEMO_SERVICE=false
VITE_OCR_API_URL=/ocr-api
```

Только `VITE_USE_DEMO_SERVICE=true` включает статические примеры без API.
Корневой `.env.example` относится к прежнему каркасу; текущий фронт
не использует `VITE_API_BASE_URL`.

## Что выполняется сейчас

1. Tesseract локально получает текст и координаты слов.
2. Backend извлекает поля и определяет наличие подписи/печати.
3. Код проверки комплектности возвращает пропуски и ссылки на пункты Положения.
4. Классификатор определяет намерение вопроса: поле, комплектность,
   окончательное решение или неподдерживаемый запрос.
5. Frontend отображает результат и формирует шаблонный ответ по классификации.

Простые вопросы классифицируются правилами, остальные - локальной Qwen.
Значения полей документа в модель не передаются. Внешние OCR/LLM API
не используются.

## Проверки

Из `frontend/`:

```bash
npm test
npm run build
```

Тесты подставляют ответы API и проверяют контракт, ответы, ошибки, лимиты
и переходы состояния формы. Они не оценивают качество реального OCR/Qwen.
Сборка включает проверку TypeScript.

Установка, самопроверка классификатора и ограничения backend-тестов описаны
в его [README](backend/online-dekanat-backend/README.md). Проверки backend
согласованы с текущим контрактом API.

Для ручной проверки можно загрузить `data/documents/open-002.pdf`,
выбрать справку об обучении и спросить «Когда началось обучение?».
Ожидаемое начало обучения - `2022-09-01`; дата выдачи в этом образце отсутствует.
Разметка для сравнения находится в `data/reference_results.json`.

## Ограничения

- Проверяется наличие сведений и отметок, а не подлинность или принятие документа.
- Требования к комплектности прописаны в коде. Изменение `data/rules.md`
  само по себе не меняет поведение приложения.
- Qwen классифицирует вопрос; backend также формирует готовый текст ответа.
- Произвольные ответы по всему Положению не реализованы. Экспорт итогового
  `results.json` доступен через CLI backend, описанный в его README.
  Одиночный ответ `/analyze` не является этим файлом.
- `docker-compose.yml` и Dockerfile фронта остались от каркаса и не описывают
  актуальный запуск обоих сервисов. Для разработки используйте команды выше.
  Размещение production-сборки требует настройки API-прокси и статических файлов.

**Open folder as vault / Открыть папку как хранилище** и укажите эту папку.
Изменения заметок распространяются через Git, а не синхронизируются мгновенно.
Не редактируйте одну заметку одновременно без согласования. Локальный
`workspace.json` не публикуется.

Используйте обезличенные тестовые документы; зависимости, веса моделей
и пользовательские загрузки не нужно включать в коммиты.
