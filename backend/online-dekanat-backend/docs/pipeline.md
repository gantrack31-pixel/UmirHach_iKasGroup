# Как работает backend

Первый запуск проекта: [DOCKER.md](../../../DOCKER.md). Нативная установка,
модели и API: [README backend](../README.md). В Docker зависимости и русская
OCR-модель включены в образ; для вопросов с Qwen требуется отдельная подготовка.
При локальном запуске рабочая папка — `backend/online-dekanat-backend/`.

## Один запрос — один документ

```text
POST /analyze: photos + document_type + непустой prompt + optional manual_fields
  → document_loader.load_image: проверить файл, превратить PDF в PNG
  → ocr_service.read_ocr: локальный Tesseract, текст и координаты слов
  → document_fields.extract_fields: схема выбранного типа и поля
  → field_extractor: метки, продолжение значения с новой строки, даты
  → marks_service: наличие графических подписи и печати
  → manual_fields.apply_manual_fields: применить допустимые ручные исправления
  → validation.service.validate_fileds: обязательные поля и источники требований
  → question_model.classify_question_for_api: правила, при необходимости Qwen
  → answer_service.build_answer: ответ из полей и результата проверки
  → JSON: OCR-текст, поля, комплектность, классификация, ответ и источники
```

Если пользователь не ввёл вопрос, frontend отправляет стандартный вопрос
«Содержит ли документ все обязательные сведения?». Backend по-прежнему требует
непустой `prompt`; специального режима API без вопроса нет.

## Ответственность модулей

| Модуль в `services/` | Назначение |
| --- | --- |
| `document_loader.py` | JPEG/PNG или одностраничный PDF, лимиты и рендер |
| `ocr_service.py` | Русский Tesseract из `models/tessdata`; текст и рамки слов |
| `field_extractor.py` | Поля справки об обучении и общие функции извлечения |
| `document_fields.py` | Выбор схемы для трёх типов документов |
| `marks_service.py` | Пиксельные эвристики подписи и печати |
| `manual_fields.py` | Проверка ключей/форматов исправлений и нормализация значений |
| `validation/service.py` | Пропуски обязательных сведений и ссылки на Положение |
| `question_model.py` | Классификация вопроса; значения полей в Qwen не передаются |
| `answer_service.py` | Детерминированный ответ и CLI экспорта `results.json` |

API закрывает загруженные файлы после обработки. Оригинал не меняется.
Наличие подписи/печати не означает подлинность. Сервис не принимает документ
за сотрудника деканата. Внешние OCR/LLM API не вызываются.

## Модели и конфигурация

Tesseract нужен для каждого документа. Локально файл русской модели должен
быть в `models/tessdata/rus.traineddata`; в Docker он скачивается при сборке
с проверкой SHA-256. Встроенный текст PDF не подменяет OCR.

Qwen3-1.7B нужна только нейросетевому маршруту вопросов. Локально веса находятся
в `models/llm`, в Docker — в именованном volume. В HTTP-запросах они не скачиваются.
Без весов такой запрос возвращает 503. Healthcheck проверяет процесс, а не
готовность OCR или Qwen. `.env` в корне читает Compose; нативный backend получает
настройки модели из переменных окружения процесса.

## Проверки

Unit-тесты в `tests/` подменяют OCR и его нативный модуль; есть проверки
загрузчика, схем, дат, переносов значений, графических отметок и API. Эти тесты
не измеряют качество реального распознавания. Команды — в README backend.

Для проверки полного пути используйте Docker и `data/documents/open-002.pdf`:
комплектность должна указать отсутствие даты выдачи. Экспорт и оценка реальных
документов описаны в [DOCKER.md](../../../DOCKER.md#экспорт-и-оценка-resultsjson).
Эталон нужен оценщику; сервис не использует его вместо OCR.
